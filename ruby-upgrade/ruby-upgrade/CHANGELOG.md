# Changelog

## Unreleased
- Bundler-vs-Ruby clarifications (from a Bundler 2.6.9 → 4.0.15 bump on fastruby/audit, on Ruby 3.4): (1) `landing-workflow.md` now distinguishes the incidental `BUNDLED WITH` bump (bundler shipped with the target Ruby) from a deliberate Bundler *major* bump, and states that Bundler's major tracks RubyGems, not the Ruby language major — Bundler 4 needs only Ruby ≥ 3.2 / RubyGems ≥ 3.4.1, so it's neither gated on nor should be smuggled into a Ruby-major hop. (2) New `known-gotchas.md` entry for Bundler 4 deprecating the per-OS windows platform symbols (`:mingw`/`:mswin`/`:x64_mingw` → `:windows`), flagged as a Bundler-upgrade concern that commonly rides along with Ruby work, not a Ruby-version issue.
- Findings from a live Ruby 3.3.11 → 3.4.9 upgrade (fastruby/audit): (1) new `known-gotchas.md` entry — a pinned linter/analyzer (RuboCop and plugins, `standard`, RBS tooling) rejects the just-bumped Ruby as an unknown `TargetRubyVersion` (`RuboCop found unknown Ruby version: 3.4`) even though the app boots and the suite is green; only the CI lint step catches it, so bump the analyzers in the same hop (rubocop 1.59.0 → 1.88.1 fixed it here). (2) `gemfile-ruby-floor-audit-workflow.md` gains a third failure mode for this "installs/runs fine but won't analyze the new Ruby" case. (3) `landing-workflow.md` Step 2 now recommends collapsing the version to a single source of truth — `ruby file: ".ruby-version"` in the Gemfile, `ruby-version-file:` in CI, drop `.ruby-version.sample` — noting `.tool-versions` and the `Dockerfile` tag still can't be collapsed (6 pins → 3 on the real app).
- Findings from a live Ruby 3.2.11 → 3.3.11 upgrade (fastruby/audit): (1) `landing-workflow.md` now lists `.ruby-version.sample` as a distinct pin and warns that a tracked `.ruby-version` can hold a value no earlier hop kept in sync — real example, a repo whose `.ruby-version` was still `2.7.2@audit` while every other pin had moved to `3.2.11`, because an earlier hop updated `.ruby-version.sample` but not the tracked `.ruby-version` beside it. (2) `deprecation-warning-sweep-workflow.md` triage gains a third bucket, "Tooling / bundler itself" — an outdated bundler emits Ruby-deprecation noise of its own (bundler 2.2.21's vendored Thor → `DidYouMean::SPELL_CHECKERS is deprecated`) that is neither app nor app-gem code and is usually cleared for free when relocking on the target Ruby bumps `BUNDLED WITH`. (3) `landing-workflow.md` Step 4 now notes the `BUNDLED WITH` bump is an expected part of the relock diff, not scope creep.
- Reworked the skill to be fully self-contained (no cross-references to `rails-upgrade` — every step, workflow, and reference now stands on its own) and to match `rails-upgrade`'s fuller directory structure instead of the leaner `upgrade-cleanup`-style layout: added `version-guides/` (2.7→3.0 through 3.3→3.4), split each workflow step into its own `workflows/*.md` file, added `references/ruby-patch-versions.md` and `references/multi-hop-strategy.md`, and added `templates/upgrade-report-template.md` plus `examples/simple-upgrade.md` and `examples/multi-hop-upgrade.md`. Strengthened Step 0 with an explicit rationale for why Ruby specifically targets the latest patch of a minor: patch releases within a minor accumulate deprecation warnings for the *next* minor's removals, so an old patch's Step 2 sweep can pass clean and still miss real breakage — a different reason than a Rails patch bump's (mostly security/bug fixes).
- Initial version of the skill. Sequential, one-Ruby-minor-at-a-time methodology mirroring `rails-upgrade`, plus a Step 2 (mandatory) deprecation-warning sweep using `RUBYOPT="-W:deprecated"` before bumping. `references/known-gotchas.md` seeded with confirmed real findings from a live Ruby 2.7 → 3.2.11 upgrade (fastruby/audit): `Proc.new`-with-no-block removal (aws-sdk v2), `URI.escape` removal (paperclip → kt-paperclip fork), re-adding `spring` after a Ruby floor is met still needing `Spring.dangerously_allow_disabling_reloading`, Docker base-image OS moves invalidating old workarounds, host-platform `bundle lock` pollution, and default gems losing implicit availability.
